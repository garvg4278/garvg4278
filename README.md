## `whoami` — A little about me

Hi, I'm **Garv Gupta**, a Computer Science Engineering graduate from **Chandigarh University (2026)**. I'm focused on building my career in **DevOps and cloud engineering**, with a broader interest in automation, backend systems, databases, and security fundamentals.

I like understanding how the pieces fit together: how an application is packaged, how a workflow moves code from a commit to a build, how a system behaves when something fails, and how repetitive work can be made more reliable through automation.

I'm early in my professional journey, so I value **hands-on practice, clear documentation, and being honest about what I've built versus what I'm still learning**. This profile is where I document that process and share the work behind it.

- 🎓 **Education:** B.E. in Computer Science Engineering, Chandigarh University, graduated in 2026
- 🎯 **Career direction:** Entry-level DevOps, cloud, or infrastructure-oriented engineering roles
- 🧰 **Areas of interest:** Linux, scripting, containers, CI/CD, cloud fundamentals, and reliable software delivery
- 🧠 **Working style:** Analytical, detail-conscious, persistent with debugging, and willing to learn unfamiliar tools
- 🎵 **Away from the terminal:** Music, playing instruments, badminton, and exploring new places

> **My approach:** Understand the problem. Make the solution repeatable. Document what changed.

## `principles` — How I like to work

| Principle | What it means in practice |
|---|---|
| **Understand before changing** | Reproduce the issue, inspect the evidence, and avoid guessing when debugging. |
| **Automate repeatable work** | If a task happens repeatedly, look for a way to make it consistent and less error-prone. |
| **Make work understandable** | Keep names, setup steps, and documentation clear enough for another person to follow. |
| **Keep learning visible** | Separate what is completed from what is experimental or still being learned. |
| **Finish the details** | Check links, edge cases, and the small issues that affect the overall experience. |

I'm analytical by nature and tend to enjoy the process of figuring out why something works or breaks. I'm also working on communicating technical ideas more clearly, because good engineering involves explaining the solution as well as building it.
